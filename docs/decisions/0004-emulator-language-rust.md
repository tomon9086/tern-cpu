# ADR 0004: エミュレータを Rust に移行する

- 状態: 採用(M2 完了後、M3 着手前)
- 日付: 2026-11-08
- 置き換え: ADR 0001

## 背景

Python 実装で測ると、ワード単位の加算は約 68 万回/秒。9 トリット加算の全網羅
(19683² ≈ 3.9 億通り)はワード単位で約 12 分、M3 のゲートレベルでは 1 桁以上遅くなり、
数時間以上かかる見込み。要件定義の「全パターン網羅」を 9 トリットでも回したい。

## 決定

エミュレータ本体(数値ライブラリ・ISA・アセンブラ・ゲートレベル)を Rust で書く。
`emu/` を Cargo パッケージとし、Python 実装は削除する(二重管理を避ける)。

## 理由

- 速度: 9 トリットのゲートレベル全網羅を現実的な時間で回せる
- `Word<const N>` でワード長を型にでき、幅の取り違えがコンパイルエラーになる
- `match` の網羅性チェックで、命令やゲートの実装漏れを防げる
- Raspberry Pi Pico でも Rust(rp-hal / embassy)が使えるので、マイコン側で再利用できる余地は残る

## 方針

- 当面は外部クレートに依存しない(標準ライブラリのみ)。並列化は `std::thread::scope` で行う
- 補助スクリプト(テストベクタ生成、SPICE 結果の照合など)は必要になった時点で言語を選ぶ
